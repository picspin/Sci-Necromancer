# 会员数据图工作区接线

## 已确认设计与实施顺序

1. 复用现有工作区、会员HTTP客户端与浏览器Python渲染；不新增依赖或云服务，生产入口保持关闭。
2. 原始CSV、原始列名和逐行数据仅留浏览器；用户确认字段别名、类型、单位和目标后才发送摘要。
3. 先补Jev摘要长度适切性、内容充分性和既有图型匹配评分，一次判别请求；程序计算字符数和硬上限，不让模型估算字数。
4. 新评估采用独立v3契约及缓存哈希，兼容既有v2图型建议和数据库v1策略；评估失败不自动调用推理模型。
5. 用户确认评估后的候选图型，再进入会员规划；任何摘要修改、账户/同意变化使旧评估与规划失效。评分不是临床准确率。
6. 会员界面隐式使用模型，保留服务端实际模型记录；隐藏模型不等于删除学分流水和最终AI披露中的模型审计。
7. 后续接第二次冻结规格确认→本地渲染→成功版本结算1学分；网络结果不明保持同任务恢复，多击和重复响应不重复扣费。
8. 区分启动权限和查看权限：零余额不清除本人已完成结果；登出/换账户清除本地状态。不上传原始数据，不把不可信浏览器回执当防伪证明。

本轮先交付第3–5项的Jev门控增量；结算状态机、免费原图授权文件及历史恢复仍按后续独立增量验收，不能据此开放生产“开发中”。仅mock/合成验证，不调用付费服务、不迁移远端、不push或部署。

## 本次实现与边界

在既有 `POST /api/jev` 的 `action=figure-route, kind=data-template` 请求上增加可选的 `assessment:true`；缺省保持旧v2建议，错误类型或其他kind携带该字段返回400。新响应为 `jev-data-figure-assessment-v3`，含 `assessment.lengthAdequacy` / `contentReadiness`，值严格限定0–1；不生成“准确率”或临床正确性标签，不据内容分私自设定通过阈值。图型仍只展示匹配值严格大于0.8的现有模板，由用户选择。

一次原有TypeSafe请求包含11个模板问题与2个摘要问题。输入只有已确认的别名、类型、单位和目标；程序添加Unicode码点计数作为长度证据，硬上限仍沿原有校验，不静默截断。提示注入样式文本只作为证据，不能改变可信问题/模型/模板。缺评分、异常值或少任何模板均整体失败；客户端和缓存都拒绝v2降级冒充v3。缓存键含新契约和完整native请求，数据库策略仍是既有 `jev-figure-routing-v1`，不引入迁移/新限流/新同意版本。

工作区请求v3，明确选中候选后才可确认冻结方案；修改摘要、模板、账户或撤销访问后失效。会员界面不再展示判别模型名，服务端返回/保存的模型审计未删。原始数据目前仅在标签页内存与独立Worker暂存；没有新增持久化CSV或隐式上传。默认col_N别名不会带原列名；用户自由输入仍可能包含PII，界面要求自行去标识化，不能宣称模型已自动移除所有隐私。

本次只是前端预览门控，不是服务端已验证Jev评估与LLM任务绑定的凭证。尚未调用现有member plan/complete接口；后续必须把本次已确认摘要绑定到同一幂等任务后，再接隐式会员规划、第二次确认和结算。不能把“可本地预览”算作“收费会员闭环已完成”，也不能把浏览器选择事件当防伪证明。

仅开发harness可传 `localValidation:true` 验证手动模板；组件同时要求import.meta.env.DEV，正式构建不可用它绕过门控。此入口本就不在生产HTML输入中；不增加生产模式开关。harness不冒充会员权限，也不调用Jev/MGA/钱包。

启动权限与查看权限已拆开：余额下降不清除现有预览，不能再启动；登录态失效或直接从会员A换成B会释放Worker并清除CSV、profile、旧预览和选择。完成版免费导出按钮仍禁用，不能据本项声称已完成零余额文件授权。

## 弱网与共享客户端修复

RED测试实际复现：fetch已返回响应头而JSON流不结束时，原客户端在headers到达就清掉超时，Promise和界面可能长期悬挂。现在同一请求deadline覆盖正文读取，外层finally释放timer/abort监听并中止遗留流，错误后可显式再次操作；保持既有401最多刷新一次、POST不跨域fallback重放的行为。组件同步busy锁阻止连续点击；cancel/身份变化后的迟到结果由epoch丢弃。没有新增自动重试或新“全局拦截器”框架。

这不等于已经做完付费任务的弱网恢复：complete响应丢失时不能当失败释放、不能换幂等键重开，仍待下一增量状态机接入。已实现SQL的幂等结算保持不变，本次未新增任何扣分调用。

## 实验与验收

- 假设：同一判别请求可返回摘要适切性/内容评分与模板候选，严格契约及失效机制可以阻止旧/异常评估进入下一步；本地验证不证明实际判别质量。
- 配置：固定合成字段/目标/评分，无随机生成；Darwin arm64、Node22.23.2、Vitest4.1.10，Python3.10.11/Matplotlib3.10.9及既有锁。浏览器报告Chrome157/MacIntel（不是CPU硬件鉴定）；网络替身只在fetch/RPC边界。没有真实用户数据、生产会话、上游密钥或付费调用。
- RED→GREEN：新增11项契约测试先因函数不存在失败；5项HTTP模式/缓存测试、v3降级测试、正文悬挂测试、账户直接切换测试均先失败再修复。旧v2测试保留，未放宽原协议以凑通过。
- 结果：110文件880项JS/TS、120项Python（37.706秒）、46项真实本地PostgreSQL（1.921秒）通过；npm run lint、build、figures:check通过。17个同源运行时文件26798136字节校验通过；原有大chunk/混合导入告警仍在。未做新的线上依赖安全审计，不能据测试通过宣称已解决既有风险。
- 浏览器：实际组件+实际memberApiClient+明确合成transport验证两评分/隐式模型、空/畸形和202/401/402/403/404/429/503、取消/数据/身份/访问切换迟到结果；320/768/1024/1440px均无横向溢出，Tab从scatter到trend，观察到page error及第三方请求为0。没有用合成分值推论模型质量。
- 浏览器渲染回归：开发手动验证harness经实际Pyodide314.0.7生成单个grouped-bar，4204×2362、599.9988DPI、sci-necromancer预览标记；观察到page error和第三方请求0。本轮没有重跑全部图型/多面板浏览器组合，不替代服务端账务或真实会员验收。
- 结论：Jev评估/UI和共享正文超时修复可本地验收；会员推理规划→渲染→结算、文件下载、历史恢复、真实上游/中国网络可达性尚未验收。
