# 数据图规划HTTP与MGA适配

日期：2026-11-21，基于e9763b1。继续用户同意的HTTP创建/规划接线；不调用付费模型、不部署、不启用线上开关。

## 实施前设计

1. 在既有 `action=data-figure` 增加 `operation=plan`，创建或重放同一幂等任务；沿用身份验证、Origin与no-store，不新增Vercel函数。
2. 本次请求必须明确确认元数据，接收幂等键、数据摘要、会员模型、可选父版本及严格规划输入；不接受用户ID、实际模型、CSV或原图。
3. 只有plan允许至多48KiB请求，内部规划输入仍受既有40KiB限制；状态/完成/导出等操作保留4KiB，避免扩大旧接口。
4. 复用已验证的预留→私有占用→校验→原子保存编排，同一任务重试不调用模型；返回pending、draft、needs_input或终态，不在规划阶段扣费。
5. 新的MGA适配复用现有服务端配置及v2归一化，采用一次fetch、超时/响应体上限、禁止重定向，不重试或回退；不改旧生文/示意图行为。
6. 发送已确认system/user元数据，请求DeepSeek或Terra的既有路由；实际模型只取响应model，缺失不猜测。供应商输出仍由可信规划解析器校验。
7. 本次元数据确认不伪装成TypeSafe/Jev同意，也不调用Jev；若用户后续使用Jev图型建议，沿既有独立同意与开关检查。
8. 真实协议适配仅以模拟fetch响应验证；前端工作区与生产入口仍未接通。Vercel规划入口最大执行时间明确配置，线上开关保持关闭。

## 请求、响应与边界

仍为 `POST /api/jev`，使用现有会员Bearer认证及Origin检查。规划请求需 `Idempotency-Key` 头，body只接受：

```json
{
  "action": "data-figure",
  "operation": "plan",
  "metadataConfirmed": true,
  "datasetHash": "本地SHA-256，64位小写十六进制",
  "model": "gpt-5.6-terra",
  "input": {
    "templateId": "grouped-bar",
    "styleId": "nature",
    "fields": [],
    "goal": "用户已审阅的目标"
  }
}
```

示例只是结构说明，fields为空不能生成有效图；实际输入遵守既有最多32字段、类型/单位和显式统计参数的契约。可选parentId用于本人已完成版本的修改。metadataConfirmed必须为布尔true；它是本次请求的明确确认，不是签名证明。自由文本别名和目标仍可能含PII，未来UI须展示出站内容并要求去标识化，不能承诺任意用户粘贴内容都没有隐私信息。

model仅接受当前两档会员ID，同价。幂等键来自请求头，身份来自服务端会话，不能在body覆写。规划返回的draft还不是最终图件或收费凭证；用户必须确认冻结规格、本地实际渲染，再调用已有complete接口结算。pending返回202及Retry-After:2；其他draft/needs_input/terminal返回200，客户端必须按kind/status处理，不能将HTTP200一概视为生成成功。

规划外层限制48KiB，只为了已确认字段摘要；内部40KiB和字段/标签/目标上限仍生效。其他五种生命周期操作继续4KiB并保持原字段白名单。未确认、伪造身份/实际模型、额外CSV/图片字段、无效输入/幂等键均不触钱包或供应商。缺余额、限流、父版本或幂等冲突由已审核SQL及编排处理，不新增价格规则。

新MGA函数只复用getMGAConfig，避免沿用旧通用文本路径的“未回报模型则采用请求模型”以及未配置MGA时的Google分支；旧生文/示意图路径完全不改。MGA请求使用现有v2 chat/completions协议，Terra映射为mga-gpt-terra-5.6，DeepSeek保持deepseek-v4.1-flash；不宣称此映射已在线验证。实际模型字段保留供应商回报ID，不用请求模型或固定名称冒充。

原生fetch只调用一次，redirect:error，无SDK自动重试或供应商回退；60秒signal覆盖原生fetch及响应读取。响应最多65536字节，既检查Content-Length，也计实际读取字节，UTF-8严格解码。错误响应/超限主动取消body，错误统一净化；不记录正文、密钥或原始供应商错误。空内容、拒绝/工具调用、截断或缺失模型元数据失败，后续编排尽力释放预留，连接故障由已有租期兜底。这里的“模型实际使用”依赖供应商回报，不是对供应商内部计算的独立证明。

## 实验与验收

- 假设：真实HTTP处理器→现有规划编排→严格MGA传输适配，在RPC/网络边界使用合成替身，可验证出站内容、模型锁定和一次调用控制；不能代替真实上游及完整会员验收。
- 配置：固定合成字段、目标、映射和测试密钥；Darwin arm64、Node22.23.2、Vitest4.1.10，Python图件回归为Python3.10.11/Matplotlib3.10.9，使用现有锁定依赖。替换Supabase工厂中的auth.getUser/rpc与global fetch，实际执行身份解析、scoped RPC、编排、纯规划校验和MGA流式读取。测试不会使用服务器真实密钥或访问模型服务。账务回归仍用固定临时pgserver0.1.4/psycopg3.2.13及最小Auth夹具，不接远端。
- RED：新增MGA模块前测试报缺模块；HTTP计划入口初始400，再接线转绿；补上明确确认、大小限制、重复请求和缺模型失败用例。旧“plan不公开”的测试项由新规划契约用例替代，不将新行为误写成向后兼容的旧拒绝行为。
- 结果：MGA传输29项、HTTP规划23项用例通过，覆盖两模型请求、v2归一化、禁止重定向/无重试、响应与请求上限、模型缺失/截断/拒绝、确认/身份、pending与缓存重放、缺项释放及数据摘要/令牌不出站。RPC是模拟边界，不是HTTP直连真实数据库的端到端验收；供应商健康、实际超时行为与真实模型回报尚未在线验证。
- 结果：46项真实本地PostgreSQL回归通过，无新增迁移或SQL变更；全量JS/TS为109文件859项（12.77秒），Python为120项（40.641秒）。npm run lint、build及figures:check通过，17个同源运行时文件共26798136字节校验通过。原有大chunk/混合导入告警仍存在，不据测试通过宣称这些问题已解决。
- 结论：协议适配代码和受门控HTTP接线完成，不是已用真实MGA成功生图。会员工作区、参数两步确认UI、失败恢复UI、原图文件导出/历史展示仍待接入；生产“开发中”不移除。
