# 会员数据图任务状态机

## 实施前设计（沿已确认工作区方案）

1. 在既有会员HTTP客户端增加规划与版本操作，仍走同源POST；不新增API、依赖、RPC或自动重试。
2. 独立前端任务控制器接收已确认的规划输入、隐式会员模型和数据哈希；不接收/上传CSV，渲染器由工作区注入并在浏览器读取原数据。
3. 新任务先冻结参数与单一幂等键，阻止重复点击；pending/网络结果不明保留请求，恢复只重放同键，不换模型或新开任务。
4. 严格检查草案与原摘要/模板/风格/参数相符；再次确认后本地渲染，哈希绑定本次规格与回执，仅收到服务器completed才展示已结算。
5. complete丢响应时先查原版本，再视awaiting_render重放同一回执；不得重新渲染、重复扣费或擅自释放不明结算。
6. 明确渲染失败/取消调用已有终态操作；迟到响应及账户切换失效，未确认取消结果不声称退款；全局客户端deadline沿用上一增量。
7. 工作区接入这套状态，保留开发harness手动验证；生产仍DEV硬关闭，原图授权文件和跨刷新历史恢复不在本增量开放。
8. 只用mock身份/传输及合成数据验证；不调用真实模型、不push/迁移/部署。服务端Jev评估与规划的强绑定仍是开放生产前的必验边界。

## 开发浏览器验证入口设计

1. 独立DEV HTML，不进入生产构建输入，不提供登录或线上入口。
2. 复用实际HTTP客户端/任务控制器/Pyodide Worker，输入固定合成CSV和已确认元数据，不用真实会话。
3. 只在fetch边界替换会员服务；模拟规划结果、状态和一次结算后丢响应，内存计数不是实际账务。
4. 显式启动→确认规格→真实本地绘图→模拟不明结果→恢复原任务；检查未重渲染/重调用供应商。
5. 仅观察本机请求、DOM/键盘/布局和控制台；不能据合成结果声称真实Jev/MGA或支付已验收。

## 接口与状态约束

会员客户端新增planDataFigure与dataFigureVersion，继续POST同源 `/api/jev`；幂等键只在规划头部，正文明确metadataConfirmed。body不带CSV/原图/客户端用户ID。规划130秒deadline，其他操作沿原客户端15秒deadline；POST不跨域fallback自动重放，401仍仅按既有逻辑刷新一次。输入快照和恢复只存在本标签页，不新增浏览器持久化或后台队列。

控制器只在新任务且有启动权限时生成一个UUID键，冻结规范化输入/模型/父版本。planning/pending/draft/rendering/settling/unknown期间锁住数据、模板、风格和参数；用户改本地原对象不能改变恢复请求。网络结果不明不能改成failed，更不能新建幂等键。已接受任务的恢复不要求余额仍大于0。

draft严格重建可信FigureSpec并比较，拒绝额外Python/模型捏造参数、模型/版本不一致、错误哈希。界面隐式使用既有DEFAULT_MEMBER_TEXT_MODEL，后台actualModel保留且后续状态须一致。第二次用户确认后才调用本地Worker；校验数据绑定、模板/风格版本、4K宽度及>300DPI等回执元数据后再结算。

特别区分两个哈希：服务端specHash是按排序JSON冻结FigureSpec的SHA-256；Python的figure_spec_sha256还包含实际数据与渲染语义，不能互换。complete发送前者，receiptHash绑定版本/前者/产物manifest，仅发送摘要，不上传CSV或图片。它仍是用户接受的不可信浏览器完成确认，不是防伪或独立绘图证明。

收到合法server completed才显示“已结算1学分”；cancel/fail/expired则按真实终态显示释放。complete丢响应先status，若已经completed直接恢复；若仍awaiting_render，重送原specHash/receiptHash，不重新调用LLM或Worker。取消竞态以服务器先到的终态为准，不能对已completed声称未扣费。渲染明确失败才fail释放；释放网络失败进入unknown，等待核对。

规划请求连版本ID也未返回时，无法安全声称已取消：先中止本地等待、保留同键，提示用户恢复标识再取消。不自动重发或另开任务“修复”。账户变化/卸载清除本地状态及中止Worker，不用新账户发送旧任务操作；服务端未确认释放的预留由已有租期兜底，刷新/导航后的历史恢复仍未实现。

## 工作区接线与未完成边界

Jev评估事件现在带回真正被确认的字段摘要，工作区只追加本地列ID、期刊风格和作者填写的显式参数。点击“确认摘要并规划”前展示实际MGA元数据与预留/成功收费说明；原始列名、CSV及逐行值不进入规划输入。得到草案后显示冻结JSON，再确认才生成。旧手动映射/导入仅留DEV localValidation harness，不能让会员随意改掉已保存规格后收费。

模型不在会员界面展示或提供额外选择；服务端真实模型记录未删除。成功/失败终态刷新会员状态，但余额刷新失败不撤销已确认结算。下载按钮仍禁用，未来无水印PNG/PDF/SVG/复现包授权免费且允许零余额；本次未新增下载扣费。

这完成了开发工作区的客户端闭环接线，不等于生产全目标完成。开放前仍须完成服务端Jev评估/同意与本任务的可靠绑定、跨刷新任务/历史恢复、原图文件授权、真实Auth/PostgREST/MGA协议与计费验收、依赖风险及中国网络可达性检查。当前仅UI门控，不能把浏览器评估事件视为服务端凭证；不移除生产DEV门控。

## 实验与验收

- 假设：冻结同键、明确unknown状态、服务端终态核对能在模拟弱网下恢复，不引发新模型/渲染/重复结算；不是对所有网络故障或真实供应商的保证。
- 配置：固定合成字段、规格、UUID/哈希夹具（新请求UUID本身随机但不用于实验指标）；Darwin arm64、Node22.23.2、Vitest4.1.10，Python3.10.11/Matplotlib3.10.9和既有锁。未添加生产依赖或新环境变量。
- RED→GREEN：客户端方法/状态模块不存在、新会员规划按钮不存在时先失败；再验证二次确认、重复点击、pending/丢规划响应、已提交/未提交完成响应丢失、取消竞态、渲染失败、错回执/旧数据、换账户、零余额恢复。没有用“超时即失败”来让状态机通过。
- 实际协议组合：真实会员客户端→真实HTTP处理器→真实规划编排/MGA适配，仅Auth/RPC/上游fetch边界替身；比较浏览器规格哈希与服务端生成哈希，故意在假RPC提交完成后丢响应，恢复只status。模拟扣费1、上游fetch1、render1；RPC不是线上SQL或完整Supabase认证，不能冒充真实扣费验收。
- 全量：111文件899项JS/TS（提交前一轮13.79秒，额度恢复后11.34秒重跑通过）、120项Python（38.309秒）、46项临时本地PostgreSQL（1.595秒）通过；npm run lint、build、figures:check通过，17个同源资源26798136字节通过。既有大chunk/混合导入警告仍在，未做新的上线依赖安全审计。
- 浏览器：Chrome157中真实控制器/客户端/Worker+合成会员transport；确认前render/debit为0，完成丢响应后各1，恢复后仍各1；请求plan→complete→status，busy复位，零余额禁新任务但保留预览。单图4204×2362、599.9988DPI，四档宽度无横向溢出，page error/console warning或error/外站请求为0。这里的debit为明确合成计数，不是真实会员学分；工作区会员组件另以渲染器/接口边界mock验证，尚非真实登录浏览器端到端测试。
- 结论：本地协议/状态与渲染回归通过；没有调用真实付费模型、连接远端数据库或部署，不能以此宣称已上线。
