# 数据图会员接口：生命周期第一步

日期：2026-11-20，基于本地提交17af87e。落实已确认的会员任务方案，不是生产发布授权。

## 实施前设计

1. 复用 `/api/jev`，以 `action=data-figure` 分发，不新增Vercel函数；数据图接口独立于会议分析/Jev开关。
2. 输入仅包括操作、版本ID及必要的规格/回执摘要或导出格式；拒绝用户ID、模型、费用、CSV、原图和额外字段。
3. 复用现有Origin检查、no-store和Supabase服务端身份验证，RPC用户ID只取已验证会话。
4. 本步支持状态、失败释放、取消、完成及原图导出授权；不开放创建/规划/标记可结算，不能靠客户端自报实际模型收费。
5. 状态RPC在钱包锁下回收过期并读取本人版本；取消/完成复用已审核的幂等结算，导出复用零余额授权。
6. 返回固定白名单的版本、钱包或授权信息，错误采用现有 `{error: code}`，不把数据库详情/堆栈泄露给用户。
7. `MEMBER_DATA_FIGURES_ENABLED` 默认未启用即关闭；本地测试通过模拟认证/RPC和隔离数据库验证，不调用真实付费服务。
8. 后续先解决跨请求的供应商调用占用/重放和规划恢复，再接真实LLM及工作区；生产“开发中”暂不移除。

## HTTP契约

`POST /api/jev`，`Content-Type: application/json`，使用现有 `Authorization: Bearer …`。请求上限4096 UTF-8字节；允许JSON的charset参数。所有操作固定含 `action: "data-figure"`、`operation`、`versionId`；UUID大小写在边界规范化。不是上传接口，不接受正文、数据行、图片或脚本。

| operation | 额外字段                                         | 服务端RPC                       | 返回             |
| --------- | ------------------------------------------------ | ------------------------------- | ---------------- |
| status    | 无                                               | get_data_figure                 | version / wallet |
| cancel    | 无                                               | settle_data_figure（cancelled） | version / wallet |
| fail      | 无                                               | settle_data_figure（failed）    | version / wallet |
| complete  | specHash / receiptHash，均为64位小写十六进制摘要 | settle_data_figure（completed） | version / wallet |
| export    | format：png / pdf / svg / reproducibility        | authorize_data_figure_export    | authorization    |

RPC身份来自服务端验证用户，客户端不能传 `userId` / `user_id` 覆盖。这里的回执仍是用户接受的不可信完成确认；规格和实际模型必须已由未来的可信规划流程绑定。本切片不能创建这个状态，也不能用于假装真实供应商调用成功。

响应只投影白名单字段，去掉数据库user_id、幂等键、请求摘要及任何新列。version含状态、父版本、数据/规格/回执摘要、请求/实际模型和时间；wallet含总余额/预留/可用余额。取消与完成竞态以数据库最终状态为准，收到200不能一概当作“已生成”：必须检查version.status。导出authorization只是owner/status/摘要/格式绑定信息，不是签名防复制凭证，不返回文件字节。

沿用 `{error: code}`。无会话401、非法Origin403、未启用404、非法请求400、过大413、非JSON415、无权限/不存在版本统一404，未可结算/摘要冲突409，余额不足402。丢迁移、畸形RPC响应或未知故障统一503，不返回或记录原始数据库错误。默认关闭的新接口不改变旧会议/Jev路由。

## 实验与验收记录

- 假设：真实身份检查后的scoped RPC＋数据库owner/终态约束，可提供小范围生命周期接口，而无需开放浏览器规划权限或上传数据。
- 配置：固定合成请求/摘要；HTTP测试只替换Supabase工厂、auth.getUser响应和RPC边界，实际执行既有requireAuthenticatedUser、Bearer解析与createScopedMemberRpcClient。数据库沿用固定临时pgserver0.1.4/psycopg3.2.13、最小Auth夹具和内置UUID策略，不接受外部数据库URL。工具未加入生产依赖。
- RED：HTTP初始调用实际返回旧Jev关闭404，尚无生命周期分发；随后补齐导出、请求大小和JSON类型。新增三个数据库状态用例先实际报不存在RPC，再加入追加迁移转绿。
- 结果：80项HTTP边界用例通过，覆盖五种操作、四种格式、伪造字段、身份/Origin、未知/畸形RPC、零余额、迟到终态及模型披露字段；34项真实本地PostgreSQL测试通过，新增状态查询/过期回收/跨用户和角色权限。数据库仍不是GoTrue/PostgREST/JWT端到端测试，HTTP模拟RPC也不是HTTP直连数据库的集成验证。
- 全量回归：106文件785项JS/TS、120项绘图Python测试（36.067秒）通过；类型检查、构建和17项同源资源检查通过。初次构建因新工作目录无dist写权限失败，授权本地构建后通过；既有大chunk/混合导入告警仍在。
- 结论：仅生命周期接口基础可本地验收，不代表真实模型规划、完整会员工作区、原图下载或网站上线完成。没有真实供应商调用、线上会员扣费或支付。
