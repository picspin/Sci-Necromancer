# 数据图第一切片：余额预留、版本状态与结算

日期：2026-11-01。用户明确接受本地回执方案，按[完整计划](./2026-11-01-member-data-figure-completion-plan.md)先实现数据库基础，不提前接通真实模型/API/UI。

## 契约与边界

- `member_data_figure_versions` 独立于会议文本版本：保存用户、幂等键、父版本、请求/数据/规格/回执摘要、请求模型与实际模型/供应商。没有CSV、患者行或图像字节；摘要不是执行证明。
- `reserve_data_figure` 在当前钱包余额上预留1学分，但不改变 `bonus_balance`、不写消费流水。返回总余额、预留数和可用余额。同一幂等键与同一输入返回原记录；换输入冲突。
- 每人最多一个活动版本，租期固定15分钟、不因重放续租；每滚动小时最多20次已接受尝试，失败/取消/过期均保留并计数。租期是本切片的保守配置，不是性能实测结果。过期在后续钱包/RPC访问时回收；扣费保护会直接忽略已到期预留，不依赖定时任务。
- 后端专用 `mark_data_figure_renderable` 绑定规划后的规格摘要和真实模型。之后不可用同一版本改写；缺实际模型不能进入可结算状态。
- `settle_data_figure` 只接受 completed/failed/cancelled。completed必须匹配已冻结规格和格式合法的回执摘要，原子地释放预留、扣1学分及写一条 `generation` 流水（`metadata.area=data_figure`，含版本/实际模型）；重复回执不再扣费，冲突回执拒绝。
- 失败、取消、过期不产生消费/退款流水。完成和取消争用同一钱包锁，先提交的一种终态生效；迟到的结果不能复活终态。父版本必须是本人已完成版本，新修改版本重新预留并成功后再扣1学分。
- `authorize_data_figure_export` 只检查格式、所有权及已完成状态，返回摘要绑定信息，下载额外0学分；不检查正余额，因此扣最后1学分后仍可授权。PNG/PDF/SVG/复现包共用边界。这只是数据库授权基础，尚没有在线下载接口或Worker原图导出接线。
- 表启用owner-read RLS；普通角色不能直接调用生命周期RPC，service_role也不能直接改版本表，须经过security-definer RPC。未来API仍必须验证用户并从服务端会话取得user_id，不能信任请求自报身份。

## 与现有钱包共存

沿用现有 `member_profiles` 行锁，新增扣减前触发器，防止文本、示意图、盲审、存储升级等余额扣减占用未过期预留；不复制或改写这些功能的既有价格规则。创建预留时更新钱包行版本，使旧 REPEATABLE READ 快照发生序列化重试，而不是漏看新预留。

Stripe原函数仅增加必要的预留兼容：退款/争议冲销若导致无法覆盖预留，先在同一锁下取消预留，再应用原有财务冲销；负余额、重复事件幂等、争议恢复规则保留。资金足以支持预留时不取消；已完成版本不会因新退款变回未完成。触发器不是防范数据库管理员主动绕过规则的边界。

## 实际实验与验证

- 假设：共享钱包行锁、统一扣减保护和终态结算可以在本地回执不可信的前提下维持账务一致；不能据此证明客户端确实作图。
- 配置：临时 `pgserver==0.1.4` / `psycopg[binary]==3.2.13`，不写入项目生产依赖/锁文件；本机PostgreSQL16.2，Python3.12.13，macOS27.0.1 arm64。数据为合成用户与固定哈希，UUID随机用于各用例隔离，不用于科研结果或性能比较。
- 数据库边界：从空临时库依次执行仓库迁移。仅提供最小 `auth.users` / `auth.uid()` 和角色夹具；临时二进制缺pgcrypto，测试跳过原迁移中安装该扩展的一句，使用PostgreSQL内置 `gen_random_uuid()`，不替换钱包SQL或伪造密码学函数。不是GoTrue、PostgREST、JWT或完整Supabase端到端验收。
- RED：先执行预留用例，真实报不存在RPC；再补生命周期/权限用例。退款回归实际重现 `insufficient_bonus` 挡住财务冲销；导出授权缺失用例实际失败；原始幂等键长度边界也先失败后修复。
- GREEN：31项真实数据库测试通过，含跨连接同时预留、重复完成、完成/取消、旧扣费/预留、退款/完成竞态，REPEATABLE READ旧快照、RLS与角色权限、零余额免费授权、争议恢复和迟到结果。不是并发压测，不能据运行时间声称提速或承诺吞吐量。
- 全量回归：105文件705项JS/TS、120项Python绘图测试（39.052秒）通过；类型检查、构建与17项同源资源完整性检查通过。构建仍有原有混合导入和大chunk告警。没有前端行为修改，不新增浏览器成功或在线模型健康的声明。
